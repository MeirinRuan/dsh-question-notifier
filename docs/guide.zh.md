# 使用与开发指南

[English](guide.md) · [README](../README.zh.md) · [许可证](../LICENSE)

## 兼容性

此 bundle 仅支持 DSH `0.2.2-rc.1`。插件使用 DSH 已有的客户端会话状态、工作区导航、语言字典和 UI Slot。其他 DSH 版本需要先检查兼容性，再修改宿主版本声明。Node.js 必须满足 `^22.19.0 || >=24.0.0`。

## 安装

从 [GitHub Releases](https://github.com/MeirinRuan/dsh-question-notifier/releases) 下载 `dsh-question-notifier.tgz`。在 DSH 插件管理中使用下载归档的绝对路径安装 bundle，然后启用。安装或更新后，如果客户端尚未刷新，请重新加载 DSH 页面。

启用此公开包前，先禁用或移除旧的 `@local/dsh-question-notifier` bundle。两者使用相同的 UI 和语言字典注册，不能同时启用。公开包名为 `dsh-question-notifier`。

在插件管理中可以禁用或移除 bundle。禁用时会卸载提醒、设置控件、字典、样式及当前实例创建的系统通知。

## 提醒行为

客户端收到待回答问题或计划审阅时，右下角会出现小浮窗，显示对话标题、首个问题的三行摘要，以及多问题请求的问题总数。浮窗宽度最多 360 像素，页面其他区域可以继续操作，也不会抢占键盘焦点。

点击“去回答”可打开对应对话。“稍后处理”、关闭按钮，或焦点在浮窗内时按 Escape，都只关闭当前提醒，原问题继续等待回答。在本次客户端挂载期间，同一已关闭请求不会重复弹出，新请求会重新提醒；多个对话的提醒逐个显示。回答、取消或请求结束后，提醒自动消失。刷新页面或重新启用插件会重置关闭记录。

## 设置与系统通知

在“设置 → 通用”中，点击“测试询问提醒”可预览浮窗，不会创建问题；点击“启用系统通知”可申请通知权限。页面浮窗不依赖该权限。

已有通知权限时，如果 DSH 页面隐藏或未获得焦点，新收到的待回答请求也会创建系统通知。点击通知会尝试将 DSH 切到前台并打开对应对话。通知在首次观察到该请求时生成；如果请求已在前台出现，之后再切换到其他应用，不会补发通知。浏览器支持、系统权限和勿扰设置决定通知是否实际展示。

## 隐私

页面浮窗显示对话标题和问题摘要。系统通知包含首个问题的文本，可能根据系统设置出现在通知中心、锁屏或屏幕共享中。只有在可以接受这些内容暴露时才授予通知权限。在浏览器或系统设置中撤销权限可停止系统通知；禁用 bundle 也会停止当前实例。

插件读取 DSH 已提供的客户端状态，仅在内存中保留关闭记录，不添加遥测、外部网络请求或问题持久化存储。通知权限由浏览器或桌面来源保存，操作系统可能保留通知历史。插件不增加模型提示、token 或会话事件，不提交答案、不自动继续任务，也不修改问题等待时长。

## 开发

使用支持范围内的 Node.js 和 pnpm `11.28.5`。在源码检出目录中执行：

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm pack --out /absolute/path/outside/checkout/dsh-question-notifier.tgz
```

`prepack` 会自动构建客户端。工作区允许 esbuild 安装构建。发布归档包含宿主入口、已构建客户端、bundle patch、中英 README、指南和许可证，安装时无需构建。构建脚本、客户端源码与测试位于 [GitHub 源码仓库](https://github.com/MeirinRuan/dsh-question-notifier)。

现有四项状态投影测试覆盖问题和计划审阅筛选、关闭去重、关闭记录清理及多对话独立提醒，不覆盖真实浏览器渲染或系统通知展示。

仓库包含市场投稿草案。投稿与发布分别处理：GitHub 仓库需创建满一天，且发布归档已可从配置的地址下载后，才能投稿。

## 限制

提醒只涵盖打开的 DSH 客户端已经收到的待回答状态。DSH 退出或页面卸载后，插件无法监测问题。系统通知需要环境支持通知 API，也可能被平台策略拦截。客户端接口尚未稳定，JavaScript 构建成功并不代表兼容其他 DSH 版本。
